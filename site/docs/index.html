Add Easel to Vite.

Easel expects a Shopify theme at the Vite root and source files in src. JavaScript works in place of TypeScript.

Requires Node.js 22.12 or newer and Vite 7 or 8.

Install Easel 
pnpm add -D vite-plugin-shopify-easel vite
vite.config.ts 
import {defineConfig} from 'vite';
import easel from 'vite-plugin-shopify-easel';

export default defineConfig({
  plugins: [easel()],
});

Add these scripts to your package.json:

package.json 
{
  "scripts": {
    "dev": "vite",
    "build": "vite build"
  }
}
layout/theme.liquid 
{% render 'easel-assets' %}
Generated output ignores 
.easel/
assets/easel-*
snippets/easel-assets.liquid

Zero configuration entry

Easel creates a bundle named theme from src/main.ts or src/main.js, plus src/style.css.

Two tools, one workflow.

Run Vite and Shopify CLI independently. Vite serves frontend assets while Shopify CLI synchronizes the theme.

Terminal one 
npm run dev
Terminal two 
shopify theme dev \
  --notify .easel/shopify-ready

The notification lets Easel request a full page reload after Shopify CLI finishes an update. It is optional. Vite HMR and Shopify CLI live reload continue to work without it.

Build, then deploy normally.

Easel publishes generated assets into the theme and replaces the development loader with Shopify CDN asset tags.

Build and push 
npm run build
shopify theme push

Run the build before shopify theme push or shopify theme package. Shopify CLI remains responsible for deployment.

Load code where it belongs.

Start with the default bundle. Add named bundles when a substantial feature should only load on selected Liquid surfaces.

vite.config.ts 
easel({
  bundles: {
    theme: {script: 'main.ts', style: 'style.css'},
    product: {script: 'product.ts', style: 'product.css'},
  },
});
layout/theme.liquid 
{% render 'easel-assets', entry: 'theme' %}

{% if request.page_type == 'product' %}
  {% render 'easel-assets', entry: 'product' %}
{% endif %}

  • Use dynamic imports first

    They keep one entry architecture while Vite loads optional features on demand.

  • Use bundles for clear boundaries

    Product configurators, account areas, and store locators are good candidates.

Small API, explicit control.

Every Easel option is optional.

vite.config.ts 
easel({
  // Theme directory relative to the Vite root.
  theme: '.',

  // Source directory relative to the Vite root.
  source: 'src',

  // Namespace for generated assets and Liquid.
  namespace: 'easel',

  // Set to false to disable coordinated reloads.
  refresh: {
    signal: '.easel/shopify-ready',
    delay: 100,
  },
});
theme
string

Shopify theme directory. Defaults to the Vite root.

source
string

Source directory. Defaults to src.

bundles
Record<string, EaselBundle>

Named script and stylesheet entry definitions. Each bundle needs a script, a style, or both.

bundles[name].script
string

Optional script entry, relative to source. When provided, script entries must be distinct across named bundles.

bundles[name].style
string

Optional stylesheet entry, relative to source.

namespace
string

Generated asset and snippet namespace. Defaults to easel.

refresh
boolean | EaselRefreshOptions

Notification file and debounce settings, or false. Enabled by default.

refresh.signal
string

Shopify CLI --notify file relative to the Vite root. Defaults to .easel/shopify-ready.

refresh.delay
number

Debounce delay in milliseconds. Defaults to 100; must be an integer from 0 to 10000.

Bring the Vite ecosystem.

Easel does not wrap frontend frameworks. Add their official Vite plugins as usual.

  • Tailwind CSS

    Official Vite plugin

  • Alpine.js

    Standard entry import

  • React

    Fast Refresh ready

  • Vue

    Single file components

  • Sass

    Native Vite support

  • PostCSS

    Native Vite config

React Fast Refresh requires @vitejs/plugin-react/preamble because Easel does not use an HTML entry. Framework code mounted inside sections should handle Shopify Theme Editor section load and unload events.

Built for a shared assets directory.

Shopify mixes generated assets and hand authored files in one directory. Easel cleans up without treating that directory like a disposable build folder.

  • Ownership ledger

    Only files recorded as Easel output can be removed as stale.

  • Isolated staging

    Every build finishes away from the theme before publication.

  • Protected writes

    Unknown theme files are never silently overwritten.

  • Recovery journal

    Interrupted publication is restored before the next build continues.

Troubleshooting

Start with the first error in the Vite terminal or your browser's Console and Network panels. A failed asset request, a blocked connection, and a missing reload need different fixes.

  • Missing styles or JavaScript
  • CORS errors
  • Browser and Theme Editor access
  • Changes do not reload
  • Localhost in a published theme
  • Protected writes and recovery
  • Entry and configuration errors
  • Framework lifecycle issues
  • Still stuck?

The theme loads without styles or JavaScript

Run npm run dev and shopify theme dev in separate terminals from the intended project. Confirm Vite reports a ready URL and Shopify CLI is previewing the expected theme.

The layout must render {% render 'easel-assets' %}, or the matching snippet for your custom namespace. The snippet is generated, so do not edit it by hand. Check the failed request in Network: connection refused means the server is unreachable; a 404 means the requested file or URL is missing. If files load successfully, check for JavaScript errors or CSS rules before changing server settings.

Use Quick start to check the setup. On a deployed theme, follow the production checks below instead of starting a local server.

The browser reports a CORS error

Easel allows myshopify.com storefronts, Shopify Admin, and localhost by default. A custom storefront domain needs an explicit allowed origin in Vite. Use the request's Origin header, including its scheme and port if present, not a URL path.

A custom server.cors setting replaces Easel's defaults. This example keeps those origins and adds a custom storefront. Replace https://www.example.com with your actual origin; add the non-www origin separately if you use both.

vite.config.ts · custom storefront origin 
import {defineConfig} from 'vite';
import easel from 'vite-plugin-shopify-easel';

export default defineConfig({
  plugins: [easel()],
  server: {
    cors: {
      origin: [
        /^https?:\/\/(?:[^.]+\.)*myshopify\.com$/,
        'https://admin.shopify.com',
        /^https?:\/\/(?:localhost|127\.0\.0\.1|\[::1\])(?::\d+)?$/,
        'https://www.example.com',
      ],
    },
  },
});

Restart Vite after changing the config. Do not use cors: true: it lets any website request your development source. See Vite's CORS guidance.

Assets are blocked in the browser or Theme Editor

CORS does not grant local-network access or make an invalid certificate trustworthy. If the browser reports a local-network permission error, check the relevant site's permission and allow access only if you trust it. See Chrome's Local Network Access guidance. Do not disable browser security globally.

A remote browser cannot reach your laptop through its own localhost. An HTTPS development endpoint or tunnel may be needed for your setup. Easel does not create tunnels and has no tunnel option.

  • For certificate or mixed-content errors, use an endpoint with a valid, trusted certificate rather than bypassing the warning.
  • server.origin tells Easel which development origin to write into the Liquid loader. It does not start a tunnel or configure its proxy.
  • If Vite says a host is not allowed, add only the exact development or tunnel hostname you control to server.allowedHosts. This is not the storefront's CORS origin. Do not set it to true.
  • The endpoint must also proxy WebSockets. Check the browser's WebSocket connection and the Vite HMR settings for your installed version. Loading JavaScript successfully does not prove HMR can connect.

A public tunnel exposes your development server. Use your provider's access controls and stop the tunnel when you finish.

Changes do not reload

  • JavaScript and CSS updates use Vite HMR. Check that Vite sees the file change and that the browser's HMR WebSocket is connected. A module without an HMR handler may cause a full reload instead.
  • Liquid changes are handled by Shopify CLI. Check its terminal for sync errors and confirm you are viewing the theme it serves.
  • Easel's coordinated reload is optional. To use it, run shopify theme dev --notify .easel/shopify-ready from the same project root as Vite. If you changed refresh.signal, use that path for --notify; refresh: false disables coordination.

The notification does not replace Vite HMR or Shopify CLI live reload. See Development for the two-terminal workflow.

A published theme requests localhost

The theme likely received a development loader. Stop Vite, run npm run build, and confirm snippets/easel-assets.liquid references assets through asset_url, not /@vite/client, localhost, or a development tunnel.

Use Shopify CLI to deploy the generated snippet and its matching assets together to the intended theme. A Git-ignored snippet still needs to be included in deployment; check any CLI ignore settings or selective upload flags. Do not run the dev server while preparing a production deployment. See Production.

Easel refuses to overwrite a file or recover a build

A file that Easel cannot prove it owns is protected. Read the path in the error and check whether it belongs to the theme, an app, or another build tool. Preserve that file; choose a different namespace and update the layout's render call if the default name conflicts.

For a publishing lock or interrupted build, first stop any other Easel processes working on the same theme, then retry the build. Easel attempts journal recovery automatically. If recovery still fails, keep the exact error and the affected files for investigation.

Do not empty assets/ or delete .easel/, its ownership ledger, or transaction journal to force a build through. Those records support safe cleanup and recovery. Easel already handles stale generated assets; a separate cleanup plugin is not required. See Output safety.

Entry files or Vite configuration are rejected

Without explicit bundles, use exactly one of src/main.ts or src/main.js, plus src/style.css. If both scripts exist, select one explicitly or remove the unintended entry. For different filenames, a different source directory, or a script-only or style-only bundle, configure source and bundles as needed.

Each named bundle needs a script, a style, or both. Provided script entries must be distinct across bundles. The theme path must point to your Shopify theme; Vite's root determines the default project location.

Easel owns its staging directory, manifest, and output naming. Remove conflicting output overrides such as build.outDir or build.rollupOptions.output rather than bypassing its safety checks. Use Easel's theme, bundles, and namespace options instead. See Configuration.

Framework components stop working after a section update

The Theme Editor replaces section markup without rerunning the whole page. Initialize or mount on shopify:section:load, and destroy or unmount on shopify:section:unload. Remove global listeners in import.meta.hot.dispose so HMR does not register duplicate handlers.

React also needs @vitejs/plugin-react/preamble because Easel does not use a Vite HTML entry. Easel does not mount framework components for you. Compare your setup with the runnable examples, including their initial page mount and cleanup.

Still stuck?

Easel supports Node.js 22.12 or later and Vite 7 or 8. Collect the installed versions from the affected project. If you use pnpm, use pnpm list in place of npm ls.

Terminal · installed versions 
node --version
npm --version
npm ls vite vite-plugin-shopify-easel --depth=0
shopify version

Open an issue with your operating system and browser version, the commands you ran, a minimal reproduction, a redacted Vite config, and the exact terminal or browser error. Include whether it happens in a CLI preview, the Theme Editor, or a deployed theme.

For network failures, include the request's status and origin after removing sensitive URL parameters. Never attach tokens, cookies, authorization headers, or an unredacted network export. Keep recovery files locally unless a specific, reviewed excerpt is needed.
